# Express checkout example

A complete, runnable checkout for any gateway supported by `india-payments-mcp`: create payment,
gateway checkout in the browser, verified return, signed webhooks. One file of server code
(`server.ts`) and one static page (`public/index.html`).

`public/start-checkout.js` is generated by the same template that `payments_generate_integration`
uses, in its multi-gateway form. It handles Razorpay, Cashfree, Stripe and Paytm JS SDKs, form posts
(PayU, CCAvenue), redirects (PhonePe, Stripe Checkout) and mock mode.

## 1. Mock mode (no account, no keys, no network)

```bash
# from the repo root, once
npm install && npm run build

cd examples/express-checkout
npm install
npm run mock            # PAYMENTS_MODE=mock tsx server.ts
```

Open http://localhost:3000 and click **Pay**. Mock mode has no real gateway, so a dialog asks
whether to simulate success or failure. Either way, the result goes through the same
`verifyPayment` → `getPaymentStatus` path a real gateway return takes, and the server logs
`PAID ... fulfil the order here` exactly once.

Try the things that should fail:

```bash
# The browser cannot change the price: the extra "amount" is ignored, you still get 49900.
curl -s -X POST localhost:3000/api/payments/create \
  -H 'content-type: application/json' -d '{"orderId":"demo-order-1","amount":1}'
```

Simulate a signed webhook. Ask your MCP client to call `payments_simulate_webhook` with
`{ "provider": "razorpay", "type": "payment.succeeded", "order_ref": "<orderRef from above>", "amount": 49900, "target_url": "http://localhost:3000/api/payments/webhook" }`
and run the `curl` it returns. You get `200 {"ok":true}`. Run it again and you get `{"duplicate":true}`.
Change one character of the body and you get `400 SIGNATURE_INVALID`.

## 2. Sandbox

1. Get test credentials from the gateway (the server prints which env vars are missing at startup,
   and `npx india-payments-mcp doctor` checks them).
2. Expose your laptop so the gateway can reach the return URL and webhook:
   `cloudflared tunnel --url http://localhost:3000` (or `ngrok http 3000`).
3. Run:

   ```bash
   PAYMENTS_MODE=sandbox \
   PAYMENTS_PROVIDER=razorpay \
   PUBLIC_BASE_URL=https://<your-tunnel-host> \
   RAZORPAY_KEY_ID=... RAZORPAY_KEY_SECRET=... RAZORPAY_WEBHOOK_SECRET=... \
   npm start
   ```

4. In the gateway dashboard, add a webhook to `https://<your-tunnel-host>/api/payments/webhook`.
5. Open the **tunnel** URL (not localhost: gateways such as Cashfree only open on whitelisted
   domains, and form-post gateways must POST back to a public URL) and pay with the gateway's test
   UPI id or card.

Swap `PAYMENTS_PROVIDER` for `payu`, `cashfree`, `ccavenue`, `paytm`, `phonepe` or `stripe` with
that gateway's env vars. Each gateway's dashboard checklist (webhook events, whitelisting, return
URLs) comes out of `payments_generate_integration` as `dashboardSteps`.

## What this example leaves out on purpose

- **Storage.** Orders and attempts live in a `Map`. Use your database, and back the webhook
  dedupe store (`createWebhookHandler({ dedupe })`) with Redis/Postgres before you run two instances.
- **Auth.** There is no login and no refund route. The generated integration
  (`payments_generate_integration` with `features: ["refunds"]`) adds an admin-only refund route.
- **Per-gateway polish.** For a real app, generate the per-gateway Express code. It splits
  service and routes and documents each gateway's trust model.

## Type-checking inside this repo

`tsconfig.json` maps `india-payments-mcp` to `../../src`, so `npm run typecheck` (after `npm install`
here) checks the example against the SDK source without building it.
